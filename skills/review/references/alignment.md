# Alignment

- **Looks for:**
    - drift from what the user asked, decided, or approved
    - scope that was added or dropped
    - breaks of the user's standing rules
    - requests the parent's requirement IDs leave out

## Procedure

1. **Establish the governing requirements**
    - You MUST reconstruct the relevant requests, decisions, approvals, and standing rules from the sources before judging the target
    - You MUST distinguish required outcomes and acceptance criteria from approved methods, intermediate work, and observed results
    - You MUST identify the user decision that changes or supersedes a requirement before treating it as changed
    - You MUST NOT treat a proposed or withdrawn change, a historical test result, or approval of a method as approval to change the required outcome

2. **Compare the target with those requirements**
    - You MUST check what the target proposes, changes, or claims against each governing requirement
    - You MUST distinguish legitimate intermediate work from a claim that the final acceptance criteria have been met
    - You MUST trace any reduced scope or acceptance target to explicit user approval
    - When the user defines an acceptance target by reference to a source, you MUST use that source rather than substitute an unrelated test result

3. **Make the verdict traceable**
    - You MUST record each governing requirement, its source, and the target's disposition in the review report
    - You MUST identify unresolved evidence needed to judge alignment and use the shared verdict rules rather than assuming compliance or inventing a requirement

- **Done when:** every request, decision, and standing rule the change touches is accounted for, with source-backed evidence for the verdict
