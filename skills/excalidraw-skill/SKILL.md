# Excalidraw diagrams

- When designing, creating, visually changing, or reviewing an Excalidraw diagram, follow [diagram design](../diagram-design/SKILL.md)
    - Before composing or rendering, read the [Excalidraw style profile](references/orestes-clean-style.md) alongside the shared style guide
    - When completeness or claim-to-scene traceability matters, use [semantic traceability](references/semantic-traceability.md), not a routine manifest
- For export-only work, use the operational guidance below without applying diagram-design steps unrelated to the requested export

## Execute and inspect

- Before canvas or server operations, read the [tool reference](references/cheatsheet.md) for interface, native conventions, shared-canvas lifecycle, and durable export
- Preserve native editability through the tool reference's semantic-arrow and annotation conventions
- Batch related operations. Use intermediate renders when uncertainty about hierarchy, geometry, or routes warrants them
- Use the native-scene audit for relevant structural integrity checks when creating or visually changing a diagram
- For rendered work, deliver the editable `.excalidraw` scene and any requested image or export with consistent content
- For export-only work, deliver the requested output without an unrelated render requirement and follow only the [shared delivery requirements](../diagram-design/SKILL.md#deliver), not its design or inspection steps
